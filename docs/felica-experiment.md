# 真卡读块实验记录（待硬件测试）

当前结论：**未接入硬件进行实验，S_PAD0 是否可读未知。** 本文件是操作步骤和记录模板，不是实测报告。

## 实验

1. 启用 CDC 和 `SKPASS_FELICA_FULL_SCAN`，保留 UART 日志。连接 Qt 等有效心跳。
2. 一次仅放一张卡，保持在线圈上直到所有扫描输出完成。记录发行方、卡版本、固件版本、脱敏卡标识、卡背号码核对结果。
3. 先读块82、再读块00，每块尝试四种线上服务字节；随后扫所有用户块00..0D、系统块80..88。每张卡理论92条探测；超时/去激活后剩余项未测试，不能算失败响应。
4. 导出 Qt 扫描日志和结果 CSV；若队列丢失，采用 UART 记录，不用不完整日志判断四种服务均失败。
5. 与卡背逐位核对有效 SPAD 解码；若读取失败则记录派生号，来源必须保留“非卡背印号”。

## 判读与待确认

* 成功需传输、长度、IDm、07响应码、Status1/2双零、块数都校验通过；可读不等于已证明是卡背号。
* A6/A7 等原始值单独记录。服务/块配置、访问控制、卡类型均可能造成失败，不能仅凭错误断言“必需认证”或“所有此类卡均不能读”。
* FF/FF 是固件未解析到卡状态的占位，可能是超时、响应损坏或 RF 错误。
* 如果四种服务全部获得明确失败响应，该卡在当前只读路径无法得到SPAD；只显示派生号。若部分未测则结论是“不完整”。
* 需要用户实测确认：各品牌真实服务字节顺序、S_PAD0可访问性、DFC、PMm、NFCC尾状态与MIFARE认证响应布局、免认证失败后是否需重新激活。
* 需要回归：同卡连续刷、不同卡交替刷、卡移走时扫描中断、USB断线重连、纯HID、实际游戏识别。

不得把“测试代码已实现”写成“真卡实验已通过”。
