# SKPass 数据 HID：自动连接与协议

适用版本：固件 **1.0.0**（数据 HID 从 1.0.0 加入）、上位机 **v1.0**。v1.0 沿用已验证的 x86/x64 AimeIO 二进制，游戏接口仍为 1.0。新增 `0x12` NFC 详情与原卡片事件独立，CDC 与 HID 使用相同 JSON，见 [NFC 协议](nfc.md)。

新增数据 HID 的目的是省去寻找 COM 号。它与原 CardIO HID 是两个独立接口：CardIO 继续给兼容程序提供原格式标识；数据 HID 给上位机和 AimeIO 提供完整读卡数据。原 CDC 保留为兼容通道，PN7150 射频状态机没有因此改写。

## 使用方式

上位机正常启动后自动寻找数据 HID，完成握手与心跳确认后显示已连接。断开后可重新选择「自动连接 SKPass USB（优先 HID）」连接；设备列表也可选择指定 `CARDIOP1` / `CARDIOP2`，或明确选择旧 COM 端口。

AimeIO 在游戏初始化后自行连接，不需要上位机作为桥接。它每秒探测设备，连接后每 10 ms 检查输入；没有设备时仍可按 JSON 配置呈现虚拟卡。

**数据 HID 以独占方式打开。** 游戏运行前，在上位机点「断开」释放设备；退出游戏后，上位机再连接。上位机断开期间仍可编辑 JSON。当前不支持两个程序同时消费数据 HID；增加 HID 接口本身不会解决所有权问题。

自动选择规则：

| 检测结果 | 上位机 / AimeIO 行为 |
| --- | --- |
| 找到并成功打开匹配的数据 HID | 使用 HID，握手并确认心跳 |
| 找到 HID，但被占用或无法访问 | 保持等待/提示占用；**不会转用 CDC** |
| 没找到匹配的数据 HID | 尝试旧 CDC，兼容未升级固件 |
| UF2 MSC 模式 | 没有读卡 HID/CDC；等待更新磁盘 |

Windows 使用系统自带 HID 驱动、`hid.dll` 和 SetupAPI，不需要安装自定义 USB 驱动或额外 HIDAPI DLL。此处是自定义厂商 HID，并非键盘，不会自动输入卡号。

## USB 描述符

正常模式 VID/PID 保留 **`1CCF:5252`**，序列号保留 `CARDIOP1` 或 `CARDIOP2`，`bcdDevice` 更新为 `0x0200`。

| 接口 | 匹配方式 | 端点 | 报告/用途 |
| --- | --- | --- | --- |
| 原 CardIO HID，接口 0 / HID 实例 0 | Usage Page `FFCA` | IN `81` | 原 9 字节报告，Report ID 1/2 |
| 兼容 CDC，控制接口 1 / 数据接口 2 | VID/PID 与 COM 枚举 | Notify `82`，OUT `03` / IN `83` | 原二进制帧，115200 / DTR |
| 数据 HID，接口 3 / HID 实例 1 | Usage Page **`FFCB`**、Usage **1**，输入/输出报告均为 64 字节 | OUT `04` / IN `84` | Report ID **1**，双向业务数据 |

关闭 `SKPASS_ENABLE_CDC` 后，CardIO 为接口 0，数据 HID 为接口 1（仍是 HID 实例 1）；两个 HID 和原始读写能力继续工作。发行默认配置开启 CDC，关闭 CDC 的构建尚未单独验证。

数据 HID 的端点包长 64 字节，描述符轮询间隔 1 ms。固件 I/O 任务每轮约 10 ms，仅提交一个输出分片；这不意味着应用层吞吐达到每毫秒一帧。更新模式单独枚举 MSC，PID `5253`，卷标 `SKPASS_UF2`。

## 64 字节报告

长度包含 Windows HID API 使用的 Report ID 字节。每份报告封装一段原业务帧：

| 偏移 | 长度 | 内容 |
| --- | --- | --- |
| 0 | 1 | Report ID = `01` |
| 1 | 1 | HID 分片协议版本 = `01` |
| 2 | 1 | 帧序号，8 位循环计数 |
| 3 | 1 | 分片索引，从 0 开始 |
| 4 | 1 | 分片总数，1～9 |
| 5 | 1 | 本片有效数据长度，1～58 |
| 6～63 | 58 | 数据，剩余位置填 0 |

被分片的完整帧仍是原格式：`CA 5A | version=01 | message | length_le16 | payload | CRC16_le16`。载荷上限 512 字节，完整帧上限 520 字节；CRC16-CCITT 多项式 `1021`，初值 `FFFF`。

接收端检查 Report ID、版本、数量、索引、帧序号、长度与容量；非末片必须恰好 58 字节。缺片或乱序时丢弃本次重组，新索引 0 可以重新开始。重组完成后仍由原解析器检查业务帧 CRC。分片序号不用于写卡去重，写卡使用原请求 ID。

## 会话与断线

每次打开数据 HID，主机生成非零 32 位会话标识，先握手：

| 方向 | 消息 | 载荷 |
| --- | --- | --- |
| 主机→设备 | `32` HELLO / 保活 | 4 字节小端会话标识 |
| 设备→主机 | `B2` 确认 | `01`（协议版本）+ 原会话标识 4 字节 |
| 主机→设备 | `33` CLOSE | 同一会话标识 4 字节 |

主机仅在收到匹配当前会话的 `B2` 后接受心跳确认设备；旧会话回复不能确认新连接。每秒发送 `32` 保活，固件租期 **3 秒**。主动关闭时发送 `33`，即使未成功发送，租期也会到期；电脑端 **5 秒**没有有效心跳就关闭连接并尝试重新发现。

新会话、关闭、拔插或租期过期会清空旧 HID 输出队列及当前发送进度，并使 HID 所属的待写请求黏性失效。CDC DTR 断开只取消 CDC 所属的请求。新连接不会自动补发旧写卡请求。

已经开始执行的卡片写入不能视为可靠撤销：可能继续完成，也可能只改完一个块。PC 断线/超时后按“结果未知”处理，重新读卡核对，不能自动重发。

## 业务功能与队列

HID 复用既有载荷，卡号仍在电脑端本地解析：

| 方向 | 消息 | 功能 |
| --- | --- | --- |
| 设备→PC | `01` | 每秒固件身份心跳 |
| 设备→PC | `10` / `11` | 原卡片事件 / 已确认离场 |
| 设备→PC | `7F` | 原 RF 诊断文本 |
| PC→设备 / 回复 | `20` / `90` | Classic 1K 限定写卡 / 结果，见 [写卡协议](writing.md) |
| PC→设备 / 回复 | `31` / `B1` | 按需查询设备信息，见 [设备信息](device-identity.md) |
| PC→设备 / 回复 | `30` / `B0` | 请求 UF2 MSC 模式，见 [固件更新](firmware-update.md) |
| PC→设备 / 回复 | `34` / `B4` | ROM 串口下载，见 [固件更新](firmware-update.md) |

数据 HID 独立队列：卡事件 1（新事件覆盖旧事件）、诊断 32、回复 16、输入 16×64 字节。队列满时不会阻塞 NFC 任务；因此诊断可能丢失，数据流并非持久日志。原 CDC 队列保留。两个通道的回复回到请求来源，全设备仍只有一个待写请求。

`skpass_cdc.c` 名称和 `SKPass_CDC_*` 内部 API 保留以减少改动，实际已承载共享 HID/CDC I/O。TinyUSB 回调只将 HID OUT 报告入队，I/O 任务解码，NFC 任务执行读写；不会在 USB 回调中操作 I²C。

## 升级与验收

旧 `pn7150_cardio` 迁移仍需完整首次烧录，见 [发行说明](../releases/v1.0/README.md)。JSON 格式和 INI 路径没有变化。

自动化已覆盖分片边界、丢片/坏片恢复、Qt 会话与占用、命令路由、AimeIO 分片读卡和 DLL 导出。验收项目：

1. 设备管理器正常枚举两个 HID 与 CDC；CardIO 工具仍能收到原 9 字节报告。
2. 上位机自动连上并可查询固件信息；拔插后恢复连接。
3. 上位机占用时游戏不通过 CDC 绕过；上位机断开后游戏正常读卡，反向也成立。
4. Classic/FeliCa 读取与旧 CDC 结果一致，重复刷入/弱耦合恢复不影响保活。
5. 在自己的可写测试卡上验证写入、取消、异常退出后重连及回读；确认旧请求不复活。
6. HID 发出更新命令后枚举 MSC，完整更新并读到 `COMPLETE`；支持自动重启的更新器约 2 秒后自动重启，上位机自动重连，再按需查询版本。旧更新器第一次装入新版仍需手动复位。
