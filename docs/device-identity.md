# 按需查询设备信息（固件 1.0.0）

在上位机的“固件更新”页点击“获取设备信息”，查询一次固件版本、构建时间、ESP-IDF、芯片型号、ELF SHA256 和当次 PN7150 状态。不会进入更新模式，不会停止读卡。详细信息只在该页显示，不自动刷新，也不常驻顶部。

`esp32/version.txt` 是应用版本来源。ELF SHA256 来自 ESP-IDF 应用描述，用来区分同版本的不同构建，不等于 BIN 文件 SHA256。当前返回完整 64 位指纹；上位机也兼容旧固件的 8～64 位十六进制前缀，明确标为前缀。

## HID / CDC 协议

沿用原 CRC16 帧、512 字节载荷上限及每秒一次的 `01` 心跳。当前标识为 `SKPass-1.0.0-retry-rom-adv-scan-ce-uf2-write`，供确认连接和判断 ROM、UF2、写卡能力。上位机默认通过数据 HID 查询，旧固件回退 CDC；载荷相同，回复只发往查询来源。[HID 握手与分片](usb-hid.md)。

- 主机命令 `31`：空载荷，查询设备信息。
- 设备回复 `B1`：一条 UTF-8 JSON，仅在收到查询命令后发送。
- 不再自动广播 `02` 详细信息。
- 旧固件可能会自动发送 `02`；新版上位机只在用户发起查询、等待回复时接受它。

```json
{
  "schema": 1,
  "firmware": "SKPass-1.0.0-retry-rom-adv-scan-ce-uf2-write",
  "version": "1.0.0",
  "built": "Oct 12 2026 18:00:00",
  "idf": "v5.2.5",
  "target": "esp32s3",
  "app_sha256": "<64位ELF SHA256>",
  "usb_state": "connected",
  "nfc_state": "ready"
}
```

上述构建时间仅为格式示例，以设备实际返回为准。`nfc_state` 是点击查询时的快照：`initializing` 初始化、`ready` RF 发现就绪、`reading` 读写处理中、`recovering` 恢复中、`update` 更新模式。它不持续反映之后的 NFC 状态，详细操作过程仍看日志。`usb_state=connected` 表示正在处理已连接通道的查询，不表示射频读取成功。

## 界面行为

连接并确认正常数据 HID 或兼容 CDC 后才能查询。查询期间按钮及固件更新操作暂时禁用；成功后恢复。3 秒无有效回复时显示超时提示，恢复操作，不自动重发。断线或设备固件身份变化会清除旧结果并取消查询。

只有正确 CRC 的 `01` 心跳才能确认设备。回复的 schema、版本、构建时间、USB 状态和指纹必须合法，固件标识必须匹配心跳。未发起查询的详细报文不会改变显示。每次主动查询即使信息相同，也正常完成。

顶部仅显示连接状态和设备确认，不显示详细固件信息。超过 5 秒未收到有效心跳（约 1 秒检测周期）会清除连接确认，并沿用自动重连设置。MSC 更新模式没有正常读卡 HID/CDC，需退出该模式并重新连接后查询。

## 使用与验证

使用 `releases/v1.0/desktop/SKPass-v1.0.exe` 和 `releases/v1.0/firmware/SKPass.bin`。UF2 更新请选择应用 BIN；当前更新器支持自动重启时等待自动重连，否则按复位键或断开全部供电再接电，在固件更新页查询。

原 CardIO、CDC 读卡事件、离场、写卡、UF2、AimeIO 功能保留。设备信息命令不执行 NFC 操作。要让游戏使用数据 HID，需要使用对应位数的 AimeIO DLL；单纯信息查询不依赖游戏 DLL。

验证使用模拟 CRC 帧和界面测试，不打开设备串口。构建和镜像校验不能替代实际 USB、读卡及更新验证。详见 `verification.md`。
