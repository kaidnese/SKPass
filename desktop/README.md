# SKPass Windows 上位机（v1.0）

这一页介绍七个页面、读写卡、虚拟卡与游戏配置、文件位置及源码构建。

直接使用：运行 [SKPass-v1.0.exe](../releases/v1.0/desktop/SKPass-v1.0.exe)（免安装）。新增 NFC 卡模拟页，自定义 UID、NDEF URL/文本、外部写入显示与 APDU 应答规则；保留高级读写、自动 HID 连接、ROM 下载和 UF2 更新。卡模拟需固件 1.0.0；参见 [卡模拟说明](../docs/card-emulation.md) 与 [高级读写说明](../docs/advanced-rw.md)。

最新修订：高级读写结果在独立表格中保留，移卡、身份续期、换卡和断线不会清空。支持复制与 CSV 导出。配套固件（1.0.0 原生支持）开放全安全区只读扫描、停止、失败/未读项重试；Classic 4K 可扫描全部 40 个扇区。扫描使用当前所选密钥，不能绕过权限，换卡立即停止。旧固件仍可普通读写，扫描按钮提示升级。

## 1. 七个页面

| 侧边栏 | 干什么 |
|---|---|

## 2. 连接与读卡

1. 把烧好固件的 ESP32-S3 接到 **原生 USB 口**（不是 USB-UART 调试口）。
2. 正常启动后默认自动连接；手动断开后可选「自动连接 SKPass USB（优先 HID）」并点「连接」。多台设备可点「刷新设备」，选择指定序列号的数据 HID；旧固件也可明确选择 COM 端口。
3. 等到绿色「读卡器已连接」。数据 HID 先完成会话握手，再以有效心跳确认设备（标识形如 `SKPass-1.0.0-retry-rom-adv-scan-ce-uf2-write`）。
4. 把卡放到天线上，看「读卡概览」。

行为细节：

* **心跳 ≠ 读卡成功**。心跳只说明 USB 通道在跑；号码能不能拿到取决于卡。
* 自动模式只在**找不到数据 HID**时回退 CDC。HID 被游戏占用或无法访问时显示提示，不借串口绕过占用。游戏实体刷卡前点「断开」；本程序仍可离线管理虚拟卡。
* **预览 10 秒后自动清空**（历史记录保留）。若固件开启了 FeliCa 全量扫描，每收到一条匹配当前卡片 IDm 的 `FELICA idm=...` 诊断行，会自动**将 10 秒倒计时重置为 10 秒**，防止长扫描中途界面被清空。
* **FeliCa 派生号不进历史表**：当 FeliCa 卡未能解出 `S_PAD0` 而回退显示 IDm 派生号时，该号码仅在概览区临时展示，**不会记入「最近刷入卡号」表格**，防止把派生号误勾选保存成虚拟卡。
* **本地解析缓存**：同一张卡（相同载荷与 `0x82` 发行方块）重复刷入时，直接复用本地缓存（容量上限 **128 张**）的解析结论。
* 心跳超过 5 秒没来 → 关闭当前 HID/CDC、清状态、提示"设备心跳超时"，然后每 1 秒尝试重连（热插拔可用）。主动点「断开」会停止自动重连。
* 坏帧会计数显示在状态栏。

卡号从哪来、为什么有时拿不到，见 [卡号说明](../docs/access-codes.md)。**本程序不联网**，没有 AiMeDB 查询。

「NFC」采用独立的 `0x12` 详情帧，CDC 与 HID 对称。所有分片通过 UID、扫描序号和字段类型校验后才显示，同卡重复扫描不会清空后重绘；交通卡号不会保存到街机虚拟卡列表。公开信息不开放时显示“未取得”，八达通旧公式余额显示“估算”。支持范围和参考来源见 [NFC 说明](../docs/nfc.md)。

在「NFC」顶部选择「交通卡识别」或「高级读写」，两页独立滚动，切换保留读取结果与输入，也不会自动发起写入。高级读写需要含 `-adv-` 能力标识的配套固件（当前 1.0.0 满足）。贴卡后选择对应地址、密钥和数据；写入要二次确认，结果显示回读数据。目标身份过期、换卡或断线会锁住操作，失败不会自动再次写入。经典卡尾块必须解锁，普通写不能写 Block 0；Gen2 UID 改写需用户确认卡型。Lite-S 仅 Scratchpad `00–0D`，Type 2 仅已确认可写用户页，ISO15693 仅实际 4 字节用户块；交通/银行无写入表单。细节见 [高级读写](../docs/advanced-rw.md)。

## 3. 写卡（只写自己的空白/可改写 Classic 1K）

前提：固件标识以 **`-write`** 结尾（当前 1.0.0 满足），并且日志里出现过 `TAG uid=... mode=00 protocol=80 interface=80 sak=08` —— 只有这一种组合才记录目标 UID，否则写卡按钮是灰的。

1. 单独放目标卡，等上面那行 `TAG` 日志；程序用**完整物理 UID** 绑定本次目标。
2. 输入 20 位非全零数字；或输入 8 位 Serial 后点生成；或点随机（随机只填输入框）。
3. 选择**卡当前使用的 Key A**：`FFFFFFFFFFFF`（空白卡默认）、`574343467632`（WCCFv2）、或自定义 12 位十六进制。
4. 点写入 → 核对弹窗里的 UID、号码、覆盖范围 → 保持或重新放同一张卡。
5. **只有"写入 + 逐字节回读校验成功"才算成功。**

| 块 | 动作 |
|---|---|
| Block 0 | 不写（保留 UID/厂家信息） |
| Block 1 | 写 16 字节 `00` |
| Block 2 | 写 6 字节 `00` + 10 字节 BCD 号码 |
| Block 3 | 不写（保留密钥与访问控制） |

必须知道的边界：

* **写号码不会改密钥**：FF 空白卡写完还是 FF，不会变成 WCCFv2；不改 UID、不改访问控制。
* **不自动重发、不回滚**：固件端待写请求有效期为 **15 秒**；CDC 掉线或 HID 会话关闭、替换、保活超过 3 秒时取消待执行请求。上位机端等待上限为 **20 秒**（超时未收到最终结果就提示"结果未知，请重新读卡，不要自动重试"）；已经开始执行的写入可能继续完成，中途移卡或掉电可能只写完一个块。
* 程序会**二次校验**固件的成功结论：即使固件报 `status=5`，上位机仍强制要求 `verifiedMask==3` 且回读数据与预期 32 字节逐字节一致，否则降级按校验失败（`status=9`）处理。
* 卡型不符（不是 Classic 1K）由固件拒绝（状态 3）。
* Key A 在本机 USB 命令里是明文，不写进日志 —— 但别公开 USB 抓包。

## 4. 虚拟卡管理

* 保存上限 **200 张 / JSON 序列化后 ≤ 64 KiB**；最近刷入记录保留 **10 个不重复**卡号。
* 号码输入会自动规整：忽略空格、`-`、`–`、`—`，全角数字转半角。校验只有：正好 20 位数字、非全零；`01036` 开头时额外校验摘要。
  **其它前缀只做格式检查**，格式合法不代表这张卡真实存在或在服务器注册过。
* JSON 结构（由本程序写出，AimeIO 只读关键的几个字段）：

```json
{
  "version": 1,
  "activeCode": "01036261387195961452",
  "keyVk": 13,
  "cards": [ { "type": "classic", "accessCode": "01036261387195961452", "note": "备注" } ]
}
```

* 刷卡键默认 **Enter(13)**，点「刷卡键设置」后直接按键录入，`Esc` 取消。**组合键、鼠标键不受支持**（AimeIO 侧也不在白名单里）。游戏里按住 = 呈卡，松开 = 移卡。
* 备注在第 3 列编辑，修改后状态栏会常驻琥珀色提示，点「保存备注」写入 JSON 后变绿并在 **4 秒**后自动隐去。
* 启用的那张卡会高亮（绿色）；一张都没启用时状态条是红色的，AimeIO 无法刷虚拟卡。
* 文件位置：默认在 **EXE 同目录的 `cards.json`**；「选择导出目录」会切到 `<目录>/cards.json`（存在则先确认覆盖）；segatools 安装成功后会自动切到游戏目录的 `cards.json`。写入用原子替换，失败不破坏原文件。

## 5. segatools 编辑

1. 关掉游戏，选 `segatools.ini` 所在目录。
2. 填 DLL 名称主体（默认 `aimeio_skpass`，`.dll` 后缀固定，且自动拦截 `CON`/`PRN`/`AUX`/`NUL`/`COM1..9`/`LPT1..9` 等 Windows 保留设备名），**手动选择加载进程的位数 x64/x86**（不会自动判断）。
3. 「读取并预览修改」→ 确认后「放入 DLL · 备份并应用」。

它只改这三项，其余内容（包括注释）原样保留：

```ini
[aimeio]
path=aimeio_skpass.dll
cardsPath=cards.json

[aime]
enable=1
```

* 应用前会把 **INI、同名 DLL、cards.json** 逐个备份为 `<原名>.skpass-<时间戳>.bak`（精确到毫秒），任一步骤失败会自动事务回滚并清理本次新建的文件。
* 通过进程快照检测到该目录下的游戏进程或 `amdaemon` 正在运行时，会直接拒绝写入并提示先关闭游戏。
* **「恢复 INI 备份」只还原 INI**（还原前会先把当前 INI 备份为 `segatools.ini.before-restore-<时间戳>.bak`），DLL 和 `cards.json` 不会一起恢复。
* INI 是 UTF-16 或含重复 `[aimeio]`/`[aime]` 段落、重复键名时会拒绝修改并提示。
* `aimeGen`、`felicaGen` 等分支特有项不会被自动改写，是否加载自定义 DLL 取决于对应 segatools 实现（见 [AimeIO 说明](../aimeio/README.md)）。
* **游戏刷实体卡前，在本程序点「断开」**：游戏 DLL 与本程序独占同一个数据 HID（旧固件使用 CDC）。程序本身不用关，虚拟卡 JSON 照常管理。内置两份 DLL，已有游戏目录需重新应用安装或手动替换。

## 6. 固件更新与设备信息

更新页分为 **UF2 磁盘更新**和 **ROM 串口下载**两个标签，设备信息查询仍在顶部。UF2 保持原操作；ROM 标签下拖入文件只会选择并校验，不会立即烧录，需点击「开始烧录」确认。

ROM 下载步骤：选择原生 USB 或外接 UART0 → 进入 ROM（显示停止读卡、USB 换号、接线和退出提醒）→ 选择固件 → 确认目标端口和烧录范围 → 写入并校验摘要 → **重新插拔 USB**。上位机随后自动寻找正常读卡器。普通更新检查分区表并保留原启动槽；首次烧录／修复使用发行包配套启动文件，需要单独确认。旧固件可手动 BOOT + RESET。详见 [完整下载说明](../docs/firmware-update.md#rom-串口下载)。

ROM 下载器识别 ROM USB-OTG `303A:0009` 与 USB Serial/JTAG `303A:1001`。全部命令使用 `--no-stub`、`--before no_reset`、`--after no_reset`；ROM 自动复位和退出按钮已移除。烧录完成或放弃下载时，请重新插拔 USB。成功提示持续保留，不会因等待重连而锁住界面。ROM 的 DFU 接口可能缺驱动，但正常 COM 通道仍可下载；本功能不使用 DFU。配套固件增加启动时 USB 断开 500ms 再连接；替换 EXE 后需关闭旧实例再运行新版。

* 选择或拖入 **应用 BIN**（上限 **6 MiB**）或 **兼容 UF2**（上限 **12 MiB**；拖放只接受单个本地文件）。
  ⚠️ 是否是 UF2 **只看文件名后缀**：把 BIN 改名成 `.uf2` 会走 UF2 校验并失败。
  BIN 会做段校验、ESP32-S3 芯片 ID（`9`）与 App 描述符魔数（`0xABCD5432`）校验、工程名必须是 `SKPass` 或 `pn7150_cardio`、末尾 SHA-256 比对；UF2 会校验每块 magic、family `0xC47E5767`、地址连续且无重复块。
* 「进入 UF2 MSC 更新模式」需要固件标识含 `-uf2-`（当前满足）：发送 `0x30` 后等待 `0xB0` 确认（**8 秒超时**；若设备正在写卡，固件会返回状态 `1` 拒绝切换）→ 设备重启变成 `SKPASS_UF2` 磁盘，读卡停止。
* 识别到磁盘后，程序会先校验 `INFO_UF2.TXT` 中的 `Board-ID`（`SKPASS-S3-N16R8-UF2-V1` 或兼容旧版 `CARDIO-S3-N16R8-UF2-V1`）并确认 `STATUS.TXT` 处于 `READY`，随后以 `FILE_FLAG_WRITE_THROUGH` 直接写入 `FIRMWARE.UF2`。
* 写入后程序以 `FILE_FLAG_NO_BUFFERING` 绕过系统缓存、每 **250 ms** 轮询一次磁盘里的 `STATUS.TXT`（**最长等待 15 秒**）：变成 `COMPLETE` 才算成功；`ERROR:` 会保留旧固件；15 秒超时则提示"不要视为更新成功"。
* 程序按磁盘 `INFO_UF2.TXT` 的 `AutoRestart` 行识别**当前更新器**：支持自动重启的更新器（v1.0 满足）成功后自动重启并自动重连；旧更新器则提示按复位键或断开全部供电重新上电。第一次用旧更新器刷入新版固件仍需手动复位一次。失败不会自动重连后假定成功。
* 「获取设备信息」是**按需查询**（MSG `0x31`，**3 秒超时**）：显示版本、构建时间、IDF、目标芯片、NFC 状态、ELF SHA256，并强制核对返回 JSON 的 `firmware` 字段与当前心跳固件标识完全一致（不一致或查询期间重连会自动作废）。**不会自动刷新**，也不会一直显示。

## 7. 文件与偏好放在哪

| 内容 | 位置 |
|---|---|
| 单文件 EXE 的运行库 | **EXE 同目录** `SKPass-v1.0-runtime\payload-<指纹>\` |
| ROM 下载临时文件 / esptool 解包 | 上述 payload 目录内的 `rom-work/update-*/`，本次操作结束后清理 |
| `cards.json` | 默认 EXE 同目录；可切到自定义或游戏目录 |
| 偏好设置 | 注册表 `HKEY_CURRENT_USER\Software\SKPass\SKPass v1.0`（继承旧 JSON/游戏目录；新增 UID 与 NDEF 输入配置） |
| 导出 CSV / 日志 | 你选择的位置 |

* 单文件启动器首次运行会调用系统自带的 `powershell.exe`（`Expand-Archive`）把运行库解包到 EXE 旁的 `SKPass-v1.0-runtime\payload-<指纹>\`。ROM 子进程的 TEMP/TMP/TMPDIR 也指定到该运行目录，避免 esptool 使用 C 盘默认临时目录。EXE 放在只读目录或系统禁用了 PowerShell 会启动失败（退出码 `3`）。
* 导出内容**不脱敏**：内存最多保留 **1000 条**刷卡记录（CSV 导出上限）与 **2000 行**诊断日志，里面都是完整号码和原始数据，掩码只在预览显示上生效。分享前自己处理。

## 9. 从源码构建

要求：**Qt ≥ 6.2**（`Core`、`Widgets`、`SerialPort`；实际验证组合是 **Qt 6.8.3 MinGW x64**）、CMake ≥ 3.21、Ninja、C++17。构建前需要先有发行目录里的两份 AimeIO DLL 和固件 BIN（会作为资源嵌入/用于测试）。

在 **SKPass 根目录**执行，路径按自己的安装位置替换：

```powershell
./scripts/build-desktop.ps1 `
  -QtPrefix   C:/Qt/6.8.3/mingw_64 `
  -CompilerBin C:/Qt/Tools/mingw1310_64/bin `
  -CMake      C:/Qt/Tools/CMake_64/bin/cmake.exe `
  -Ninja      C:/Qt/Tools/Ninja/ninja.exe

./scripts/package-desktop.ps1 `
  -QtPrefix   C:/Qt/6.8.3/mingw_64 `
  -CompilerBin C:/Qt/Tools/mingw1310_64/bin
```

* 目标：库 `skpass_core`、程序 `skpass_desktop`（`OUTPUT_NAME` 为 `SKPass`，输出 `build/SKPass.exe`）。
* 脚本会自动跑 CTest，失败即中止。包含 NFC 详情、高级读写、卡模拟 CDC/HID 与界面测试，以及既有更新、预览、JSON 和游戏配置回归。测试不烧录真实设备。
* Windows HID 使用系统 `hid.dll` 与 SetupAPI；共享层在 `../shared/`，不额外捆绑 HIDAPI 运行库。
* 首次构建自动调用 `scripts/prepare-esptool.ps1` 下载并校验官方工具（需网络）；缓存位于 `desktop/build/tools-downloads/`。先编译并导出固件到 `releases/v1.0/firmware/`，供首次烧录文件打包及测试使用。两份 AimeIO DLL 的 API 保持 1.0，无需为 CE 修改游戏接口。
* 打包流程：`windeployqt` 收集运行库 → 加入 esptool 与配套首次烧录文件 → 压成 zip → 用 `windres`+`gcc` 嵌进启动器 → 输出 `releases/v1.0/desktop/SKPass-v1.0.exe`。

验证现状见 [验证记录](../docs/verification.md)；第三方算法与表项见 [来源声明](../THIRD_PARTY_NOTICES.md)。
